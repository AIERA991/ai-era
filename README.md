# AI Era · AERA

连接 AI 服务与日常交易的结算协议原型。**已创建源码并在本地模拟区块链验证，尚未在公共测试网或主网发行，没有公开代币地址。**

## 已确认的产品方向

**提供真实 AI 服务，获得客户支付的 AERA 报酬。** 首个场景是帮助小商家翻译商品介绍、整理商品资料，跑通“发布需求 → AI 交付 → 验收付款”。报酬来自客户付款，完成任务不会增发代币；当前没有挖矿或自动收益功能。

详见 [商家 AI 服务方案](docs/MERCHANT-AI-SERVICES.zh-CN.md)。这是开发方向，商家服务平台尚未上线；主观翻译质量仍需客户验收，不能用小模型计算演示替代。

## 研究与原型

最新产品定位见 [AI 与日常生活交易设计](docs/EVERYDAY-TRANSACTIONS.zh-CN.md)：将有限授权的 AI 助手、真实商品与服务、结算及售后凭证关联起来，强调供给上限、资金安全与隐私。现实商家接入、授权钱包及隐私功能仍是待实现需求。

最新方向见 [V2 协议设计](docs/PROTOCOL-V2.zh-CN.md)：自主运行、市场定价、可验证 AI 执行及隐私。新增 `AIVerifiedEscrow.sol` 与 `LinearInferenceVerifier.sol` 已实现小模型计算通过后自动付款；隐私、独立公链与储备自动释放尚未实现。下文人工仲裁合约是 V1 对照原型，不是 V2 最终架构。

## 确认的发行规则

名称 AI Era，简称 AERA，总发行量 21,000,000 枚，8 位小数。

| 用途 | 比例 | 数量 | 首次接收位置 |
|---|---:|---:|---|
| AI 社区贡献奖励 | 65% | 13,650,000 | 社区储备地址 |
| AI 生态基金 | 20% | 4,200,000 | 生态资金地址 |
| 初始流动性储备 | 10% | 2,100,000 | 流动性储备地址 |
| 开发者 | 5% | 1,050,000 | 合约自动创建的开发者锁仓地址 |

代币在构造时一次性分配，没有后续增发、管理员改余额、暂停、黑名单、转账税或升级入口。开发者地址在部署时确定，不能通过锁仓合约修改。

开发者锁定 365 天；随后 1,460 天按秒线性释放。锁定期结束时可释放数量仍为零，部署满 1,095 天约释放一半，满 1,825 天全部释放。“年”按 365 天计算，不是日历周年。任何人可调用 release，但只能付给指定开发者地址。

社区、生态及流动性储备目前没有链上支出限制，其接收钱包掌控全部对应份额。5% 是直接分配给开发者的额度，并不能证明开发者不控制其他钱包。正式发行前应落实独立多签、公开签名人和支出规则。流动性储备不代表已经创建交易池、锁定流动性或存在市场价格。

- `docs/LAUNCH-PLAN.zh-CN.md`：生态启动方案及参考来源。

## 本地运行

安装受 Hardhat 支持的 Node.js 22.13+ 或 24 LTS 及 npm，在本项目目录运行：

```sh
npm ci --ignore-scripts
npm run compile
npm test
npm run demo
npm run demo:verified
```

`compile` 生成本地 EVM ABI、字节码及编译输入。编译器固定为 Solidity 0.8.30，优化 200 次，EVM 目标 Paris；OpenZeppelin Contracts 固定为 5.4.0。

`demo` 自动启动内存链、部署合约、为模拟客户分配 100 枚、托管 25 枚、提交固定示例结果、客户验收付款，随后关闭链。它不连接钱包、不花真实资产、不调用真实 AI。报告保存在 `reports/local-demo.json`；其中地址只在该次本地运行有效，不是公开发行地址。

本地链使用 Hardhat 3.15.0 的内存模拟网络，不监听公开 RPC 端口。`demo:verified` 演示固定小模型计算与自动结算，无需客户验收，模型输入及交易金额公开。

## 调用真实 AI

先在自己的计算机启动 Ollama，并安装可运行的模型。PowerShell 示例：

```powershell
$env:OLLAMA_MODEL = '填写你已经安装的模型名称'
npm run agent
```

默认只连接 `http://127.0.0.1:11434`。可以通过 `OLLAMA_URL` 指定自己信任的服务；任务提示词会发送给该地址。

结果写到 `reports/ai-specification.json`、`reports/ai-result.json` 和 `reports/ai-hashes.json`。前两个文件是紧凑 UTF-8 JSON；哈希是其精确字节的 Keccak-256。修改空格或内容会改变哈希。创建任务时使用 specificationHash，服务提交时使用 resultHash。当前命令不持有签名密钥，不自动发送区块链交易。

链上只存哈希和结算状态，原始需求与结果须由双方保存并交付。哈希不能证明作品质量、确实使用了某个模型、内容原创或数据真实；模型身份来自推理端自报。示例未提供可信执行证明或自动质量预言机。

## 任务资金规则

1. 客户指定服务方、独立仲裁人、金额、任务哈希和交付截止时间（最长 90 天），授权并存入 AERA。
2. 指定服务方在截止时间前提交非空结果哈希，开始七天验收期。
3. 客户可以批准付款；七天内可以提出争议。客户超过七天未争议，任何人可触发付款给服务方。
4. 未按时交付的任务，任何人可触发退回客户。
5. 有争议时，仅该任务预先指定的仲裁人能在十四天内决定支付给服务方的份额，其余退客户。
6. 仲裁超过十四天未完成，任何人可触发全额退客户。**此兜底偏向客户，服务方必须接受并信任选定的仲裁人。**

该版本不含接单确认步骤；服务方应先在链外同意任务条款，客户再创建任务。合约不会自动验证 AI 身份。使用其他收费、重基准或恶意代币未获支持；该托管合约设计用于本项目 AERA。

## 当前边界

这是工程原型，不是独立安全审计。不存在“绝对无法破解”保证，也尚未实现抗量子账户体系。锁仓受益人私钥泄露仍有风险；误转到锁仓的额外代币没有取回入口，误转到任务托管的非任务资产也没有救援入口。

尚未完成：公共测试网部署、TRON TVM 编译与集成验证、真实模型端到端验收、钱包界面、自动任务接单、信誉系统、服务保证金、生态多签及主网发行。不要将这些规划描述为已上线功能。

核心供给不可升级；需要更换业务时可以部署新的任务合约，但不会改变原代币。项目未与孙宇晨、TRON DAO、交易所或模型厂商建立合作关系。
